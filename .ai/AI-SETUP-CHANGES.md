# AI setup hardening

This update focuses on three controls:

1. Security-sensitive hooks fail closed instead of silently allowing operations on errors.
2. Write operations whose filesystem targets cannot be resolved are denied rather than
   treated as implicitly safe.
3. Implementers are required to have a machine-verifiable approval artifact identifying
   the approved plan/work package and scope.

Review the existing agent/skill instructions alongside `AI-APPROVAL-CONTRACT.md`.

# Provider-agnostic restructure

The setup no longer depends on GitHub Copilot. Sources of truth are `AGENTS.md`, `.ai/` and `.agents/skills/`; per-host files are generated by `node .ai/scripts/sync.mjs` (see `.ai/README.md`).

- `.github/copilot-instructions.md` became `AGENTS.md`; the Copilot file is now a generated pointer. `CLAUDE.md` imports `AGENTS.md`.
- `.github/instructions/` moved to `.ai/instructions/`; Copilot and Claude Code copies are generated.
- `.github/agents/` moved to `.ai/agents/` with neutral frontmatter (`access`, `model-tier`); Copilot, Claude Code and Codex agent files are generated.
- `.github/skills/` moved to `.agents/skills/` (read natively by Copilot and Codex); a Claude Code mirror is generated.
- `.github/hooks/guards.mjs` moved to `.ai/hooks/guards.mjs` and now understands Copilot, Claude Code and Codex events. Hook configs for each host are generated.
- Model names left the skills. They use the `default` / `escalation` tiers resolved in `.ai/providers.json`.
- Guard behaviour changes: the `|| true` / `exit 0` wrappers that swallowed guard failures are gone, an unprocessable event now actually denies, a write whose target cannot be resolved is denied, protected paths cover all host directories plus `AGENTS.md`/`CLAUDE.md`, and shell-delivered `apply_patch` is checked. `COPILOT_ALLOW_GUARD_EDITS` and `COPILOT_ALLOW_GIT_WRITE` still work but are superseded by `AI_ALLOW_GUARD_EDITS` and `AI_ALLOW_GIT_WRITE`.
