# Repository agent instructions

Canonical, provider-neutral instructions. Codex, GitHub Copilot, Cursor and most agent hosts read this file natively; Claude Code imports it through `CLAUDE.md`. Edit only this file for repo-wide rules; never copy its content into provider-specific files. How the setup fits together: `.ai/README.md`.

## Plan gate
- Before changing tracked files, present a complete written plan and wait for explicit approval. Approval covers the plan as written, not a summary of it.
- Use the host's native mechanism when it has one: a plan mode / exit-plan tool (`exit_plan_mode` in Copilot CLI, `ExitPlanMode` in Claude Code) or a question tool (`ask_user`, `AskUserQuestion`) offering Approve / Request changes.
- If the host has no such tool, show the plan in the conversation and wait for an explicit approval reply; never infer approval.
- A trivial change still gets a three-line plan. Do not implement before approval.
- An implementer may act only on one approved work package (WP); it must not ask for approval again. The handoff must quote the approval (the user's reply or the maintainer's approval comment, see below).
- Stop and request a revised plan if implementation exceeds the approved scope.
- Cloud / asynchronous agent work (Copilot cloud agent, Codex cloud, Claude in GitHub): put the plan in the PR description and make no code changes until a maintainer comments approval addressed to the agent that is running (`@copilot approved`, `@codex approved`, or `@claude approved`). Only comments from repository owners, members, or collaborators count.

## Repository map
- Backend: .NET 10 and HotChocolate 16 in `RefTestManagement.Api`, `RefTestManagement.Domain`, `RefTestManagement.Application`, `RefTestManagement.Infrastructure`, `RefTestManagement.Security`, and `RefTestManagement.Auth0`.
- Database providers: `RefTestManagement.Migrations.SqlServer`, `.PostgreSQL`, `.SQLite`, and `.MySQL`. Tests: `RefTestManagement.UnitTests`.
- Frontend: Angular 22 in `RefTestManagement.Ui`. GraphQL documents are in its `graphql/` directory.
- AI control surface: `AGENTS.md`, `CLAUDE.md`, `.ai/`, `.agents/`, `.claude/`, `.codex/`, `.cursor/`, `.github/hooks/`, `.github/agents/`, `.github/skills/`, `.github/instructions/`, `.github/copilot/`, `.github/copilot-instructions.md`, `.github/CODEOWNERS`. These change only when the user explicitly asks; hooks block agent edits to them. Sources of truth are `AGENTS.md`, `.ai/` and `.agents/skills/`; everything else is generated by `node .ai/scripts/sync.mjs`, so edit the source and re-run it.
- Start with `README.md`; see `docs/CONFIGURATION.md`, `docs/SECURITY.md`, and `docs/AUDIT-R*.md` for operational rules and audit history.

## Workflows
- `audit` and `deliver` are agent skills in `.agents/skills/`. Invoke them with your host's syntax (`/deliver` in Copilot CLI and Claude Code, `$deliver` in Codex) or simply ask for them in words.
- Subagent roles `auditor` and `implementer` are defined once in `.ai/agents/` and generated for each host. A host without subagents performs the role inline, following the same rules.

## Build and test
- Backend build: `dotnet build RefTestManagement.slnx -nologo -v q -clp:ErrorsOnly`.
- Targeted backend test: `dotnet test --solution RefTestManagement.slnx --configuration Release --filter-class Handball.Belgium.RefTestManagement.UnitTests.AuthorizationTests`. MTP requires `--solution`; use `--filter-class` or `--filter-method` for xUnit v3.
- UI spec (run in `RefTestManagement.Ui`): `npm test -- --include src/app/privacy/privacy-notice.spec.ts --watch=false`. Also run `npm run check:i18n` and `npm run build -- --configuration production` when affected.
- `npm run codegen` requires a running API.
- Done means the build and affected tests pass; report any check that could not run.
- Backend tests use xUnit v3 on Microsoft.Testing.Platform: add them to `RefTestManagement.UnitTests` and target them with `--filter-class` or `--filter-method <fully-qualified-method>`.

## Invariants
- Use only Conventional Commit types/scopes from `commitlint.config.mjs`; commit and PR-title headers are at most 100 characters. PR bodies use `Closes #N`.
- Preserve XML documentation, JSDoc, and comments that explain why.
- A GraphQL operation needs a permission constant in `Permissions.cs`, `[Authorize(Policy = ...)]`, and a matching entry in `docs/SECURITY.md`. Record security-relevant state changes in the audit log.
- An EF model change needs a same-named migration in `RefTestManagement.Migrations.SqlServer`, `.PostgreSQL`, `.SQLite`, and `.MySQL`. Use the commands in `docs/CONFIGURATION.md`.
- Keep `[LoggerMessage]` methods in static partial classes. Never log participant PII, secrets, or unredacted exception data that may contain them.
- Put user-visible UI text in all four locales: `en`, `nl`, `fr`, and `de`.
- `main` is protected and every push triggers a pre-release; do work on `feat/*`, `fix/*`, or `chore/*`. Never commit or push unless the user explicitly asks, and never push to or from `main`. Agent hooks additionally deny commit/push by default, including `--all`, `--mirror`, and `--tags`.
- Implementation writes require `.ai/approvals/active.json`, whose plan/WP/file scope is validated by the guard. A missing, expired, tampered, or out-of-scope approval denies the write.

## Token hygiene
- Do not read lock files, `RefTestManagement.Ui/graphql/generated.ts`, `docs/Audits/AUDIT*.md`, or locale JSON in full. Search first, then use ranged reads.
- Run `git diff --stat` before reading a full diff.
- Send long build, test, or hook output to a temp log and show only errors or a short tail.
